Разбор

Разговор о замедлении ИИ обострился после слов бывшего исследователя OpenAI и Anthropic, что компании «играют с нашими жизнями», и после того, как в заявке Anthropic на IPO риски назвали «катастрофическими или экзистенциальными» для общества.   3. Бенчмарки на прикладные задачи (downstream capabilities) быстро устаревают, а перплексия, по его аргументу, остаётся информативной.
  4. Предложенный порог: компании обещают не переходить его, пока понимание и мониторинг поведения ИИ не достигнут «конкретной вехи».
  5. Сэм Альтман назвал пост «самым важным, что OpenAI опубликовала за последнее время».

05Хакеры через облачное управление взломали роутеры и KVM GL.iNet

bleepingcomputer.comприменяют

GL.iNet сама подтвердила: через уязвимость в облачном сервисе удалённого управления хакеры залили вредонос на роутеры и KVM клиентов. у части пострадавших есть бэкдоры и , то есть взломщик получает удалённый доступ к железке. если у вас в сети стоят их роутеры с облачным управлением, смотреть на них надо в первую очередь, через этот сервис и ставили вредонос. ну и хуёво же, конечно.

Разбор

GoodCloud — облачная панель, через которую можно управлять роутерами и KVM (устройствами для удалённого управления чужими компьютерами), так что взлом облака открывает и подключённые к KVM машины. По меткам времени части вредоносных файлов видно, что заражения могут тянуться с декабря 2025 года, а не только с ноября.

  1. Признак заражения из рекомендаций GL.iNet: процесс, который выдаёт себя за системный планировщик crond и запущен как crond -i /tmp/.log.
  2. Заражённое устройство само открывает исходящее соединение к 170.39.226[.]219 через утилиту nc (netcat, инструмент для сетевых соединений), и атакующий выполняет на нём команды.
  3. Скрипт, который подменяет утилиту netstat (показывает открытые сетевые соединения), фильтрует из её вывода связи с 66.245.219[.]252, так что администратор их не увидит.
  4. В клиенте GoodCloud исследователи RemoteToHome нашли возможную command injection: обработчик для AstroWarp/SD-WAN (программной сети между филиалами) передаёт значения из облака в shell-команды с правами root без проверки. GL.iNet не подтвердила, что эту дыру использовали в атаках.
  5. RemoteToHome проверили 183 роутера, которыми владеют или управляют, и нашли подозрительную активность на 152: у 24 были root-шеллы, у 47 старый постоянный бэкдор, у 81 видны выполненные атакующие команды.

Community-сканер проверки и очистки, на который GL.iNet сослалась в официальной поддержке для роутеров и KVM: ищет известные вредоносные файлы, подозрительные процессы, подменённые системные утилиты и правки для закрепления, может собрать улики и удалить известные компоненты. Прошивку для KVM берём версии 1.10.3 или новее (RM10, RM1, RM1V2, RM1PE, RM4PE), для RMQ1 — 1.8.7 или новее.

ОграниченияОблачную дыру закрыли, но уже заражённые устройства это не чистит. Сканер не находит все заражения, и при подозрении может понадобиться переустановка прошивки без сохранения настроек, потому что вредоносные файлы в каталогах конфигурации переживут обычное обновление. Патчи с дополнительными исправлениями запланированы только на 22 ноября 2026.

06Агент в трети git push не спросил разрешения, трижды запушил в main

habr.comприменяют

блин, тут много чего. из 193 пушей в трети случаев агент не спросил, хотя в agents.md черным по белому написано «не работай в main» и « только с разрешения». трижды запушил в main. из 31 force push автор разрешил всего два. а этот же агент ходит в бд, s3 и kubernetes с правами самого автора. вывод автора такой: текст в agents.md агент не держит, поэтому ограничивать доступ надо в самих инструментах и правах, а не в промпте. ну вот и приехали, на одних инструкциях в промпте полагаться нельзя.

Разбор

Агент в статье — OpenCode, он работает в стеке Airflow, Spark в Kubernetes, Kafka, S3 и Trino, где автор, ведущий разработчик Magnit Tech, собирает данные для прогнозных моделей и BI. Инструкции в AGENTS.md — это файл с правилами, который агент читает перед работой, а не механизм, который их принудительно соблюдает.

  1. Из 193 вызовов git push 169 прошли успешно; после появления правила «спрашивай перед пушем» 39 из 109 ушли без спроса.
  2. Хук PreToolUse (в Claude Code) срабатывает перед вызовом инструмента, его нельзя отключить из сессии, и при сбое он блокирует действие (fail closed).
  3. На последнем уровне агенту выдают отдельную идентичность: через ограниченный интерфейс доступны только разрешённые операции, всё остальное отклоняется, а проверка встроена в CI или merge.
  4. В бенчмарке ImpossibleBench модели получали задачи, которые без нарушения спецификаций не решить: они начинали править тесты и перегружать методы, выдавая желаемое за действительное.
  5. По словам автора, агент пользуется любой лазейкой, поэтому main нужно закрывать защищёнными ветками GitLab, которые запрещают прямой push.

Примеры в статье написаны под Claude Code (хуки PreToolUse); для OpenCode механизм настраивается через tool.execute.before. Песочницу можно собрать на Daytona (сервис изолированных сред для агентов).

ОграниченияХук видит только распознанные команды: обходы через другие команды, скрипты и интерпретаторы он не закроет. Для OpenCode готовых OSS-решений мало, их поддерживают не так активно, как для Claude, так что многое придётся доделывать самому.
