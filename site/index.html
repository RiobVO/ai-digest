01Совет Nvidia вернул Хуанга в CEO через 11 дней после отставки

wired.com3 источникаприменяюттакже: Ars Technica, SCMP

Дженсена Хуанга вернули на пост главы Nvidia, хотя он ушёл 12 ноября. На первом всем-хэндах он извинился перед сотрудниками и признал, что его жёсткий стиль управления вредил людям. По данным SCMP, акции Nvidia после новости выросли больше чем на 30%.

Разбор

Уход Хуанга случился после публикаций о внебрачных романах, в одном из которых фигурировала женщина, по обвинениям связанная с китайскими спецслужбами. Совет тогда назвал причиной личное поведение и недостаток откровенности. Вернули его после новых заверений и после того, как администрация Трампа сообщила, что федерального уголовного расследования против него нет и возвращение не угрожает нацбезопасности.

  1. Совет проверяет, не был ли Хуанг целью иностранной разведки.
  2. Американские законодатели ждут его показаний в Конгрессе на следующей неделе.
  3. Иски и проверки продолжаются: по раскрытию информации о его поведении и по соблюдению экспортного контроля на чипы, то есть правил, по которым чипы нельзя свободно продавать в определённые страны.
  4. Хуанг предложил пройти 360⁠-⁠градусную оценку: отзывы от коллег раз в месяц, но только для себя, без распространения на всю компанию.
  5. У него 60 прямых подчинённых, каждый руководит своим подразделением, и из них, по словам Хуанга, можно выбрать преемника. Планирование преемников он назвал ошибочным процессом.

02Claude Ship: агент сам решает, одобрить ли pull request в GitHub

theregister.comдоступно

агент сам решает, мержить ли pull request, и ставит апрув вместо человека. если уже работаешь с claude code и github, это прямо задевает твой процесс ревью. ну, охуеть, посмотрим, как это зайдёт.

Разбор

Очередь на ревью стала узким местом: ИИ⁠-⁠кодеры выдают больше кода, и pull request'ы ждут людей дольше, чем пишутся. Anthropic отвечает на это ещё одним ИИ, который ревьюит и апрувит сам.

  1. Claude Ship собран из общедоступного Code Review и двух новых агентов в бете: PR Steward разбирает упавшие CI-проверки, конфликты слияния и замечания ревью, Claude Approvals ставит апрув.
  2. Доступно клиентам Claude Team и Enterprise с репозиториями на GitHub.
  3. Claude Approvals берёт правила из файла-политики в репозитории. Anthropic советует сначала включить режим observe-only (только наблюдение), а потом требовать его зелёный свет через branch protection (правила защиты ветки).
  4. Админ может выбрать, с какого репозитория начать, задать лимит расходов в месяц и решить, когда запускаются ревью.
  5. Оплата токенами: даже в режиме наблюдения расходы идут, если вызываются классификаторы или Code Review. Апрув при этом не равен мерджу: существующие правила ветки и обязательные проверки остаются в силе.

Нужен план Claude Team или Enterprise и репозиторий на GitHub; свои pull request'ы можно пробовать через Claude Code.

ОграниченияОба агента в бете. Anthropic прямо пишет, что ИИ может пропустить баги и уязвимости, а расходы растут вместе с объёмом проверок.

04Через дыру в Azure API Management крали токены и секреты

thehackernews.comприменяют

норвежский NSM пишет, что неизвестный шарился в Azure API Management и искал токены доступа, секреты и именованные значения. под раздачу попали несколько компаний, в том числе энергетики Equinor и Skagerak Energi. microsoft уже закрыла дыру. если твои API стоят за azure apim, то ключи и токены, которые там лежат, как раз и были целью, так что проверь их прямо сейчас, это не шутки.

Разбор

Уязвимость касается только классического тира APIM, и опасна она не только сама по себе: утёкшие секреты работают дальше, пока ключ действителен. Именно поэтому Microsoft просит клиентов менять секреты, а не просто ждать исправления.

  1. Microsoft обнаружила проблему 18 ноября и закрыла путь доступа 19 ноября 2026 года; инстансы на тирах v2 не затронуты.
  2. Под угрозой могли оказаться секреты из Named Values (хранилище настроек и секретов внутри APIM), клиентские секреты провайдеров входа и OpenID Connect, ключи подписки и токены для прямых управляющих API.
  3. Руководство по поиску и смене секретов Microsoft выпустила 21 ноября; количество затронутых клиентов компания не раскрыла.
  4. По словам исследователя Anders Kristiansen, злоумышленник с украденным ключом может использовать его прямо против защищаемого сервиса, а что он сможет сделать, зависит от прав ключа и от того, действителен ли он ещё.

Проверь тир своего APIM: если это классический, а не v2, ты в зоне риска, и стоит пройтись по руководству Microsoft по смене секретов.

ОграниченияПодробности известны из неопубличного уведомления Microsoft, масштаб эксплуатации пока не ясен.

Разбор

07В settings.json добавь хук PreSkillShellCommand, чтобы отсекать shell-команды навыков

github.com

Почему важноХук может отказать в inline shell-командах навыка или команды ещё при загрузке, до их выполнения.

Открой свой settings.json и пропиши в нём хук PreSkillShellCommand; нужна версия 2.1.332 или новее. На 2.1.331 и старше файл с этим именем при старте откроет диалог.

Команда или промпт
PreSkillShellCommand
Разбор

В этом же релизе Claude Code научился подключать навыки из MCP-серверов (в бете): они показываются в меню / как server:skill. Внешние навыки и их встроенные shell-команды теперь попадают в сессию, и новый хук позволяет отсекать часть из них при загрузке.

  1. Обнови Claude Code до версии 2.1.332 или новее.
  2. Открой свой файл settings.json.
  3. Добавь в settings.json хук PreSkillShellCommand, который отказывает в запуске встроенных shell-команд навыка или команды при загрузке.

Релиз v2.1.332 лежит на GitHub на странице релизов Claude Code.

ОграниченияНа версиях 2.1.331 и старше файл с этим именем при старте откроет диалог.

09Армин Ронахер хочет убрать отравление мьютексов из Rust

lucumr.pocoo.orgдоступно

в rust, если код упал с паникой, держа мьютекс, он помечается отравленным, и следующий lock() возвращает ошибку. ронахер считает, что сегодня такого механизма в язык бы не добавили и хочет его убрать.

Разбор

Отравление мьютексов — механизм, который Rust унаследовал из старых версий, и его нельзя просто выключить одним решением: стандартная библиотека сама его игнорирует. Поэтому команда libs обсуждает, чтобы в следующей редакции языка замки по умолчанию не отравлялись.

  1. Clear_poison (сброс флага отравления) появился только в Rust 1.77, а первые девять лет флаг сбросить было нельзя.
  2. PoisonError держит сам замок, поэтому m.lock()? в функции, возвращающей Box<dyn Error> (универсальный тип ошибки), держит мьютекс, пока жива ошибка, и это ведёт к взаимной блокировке.
  3. В Mozilla application-services PoisonError поднялся в топ⁠-⁠5 краш-статистики, и команда перешла на parking_lot.
  4. Tokio оборачивает std-замки в адаптер, который убирает отравление, а сама стандартная библиотека игнорирует его в стандартном I/O с марта 2015 года.
  5. Ронахер предлагает стабилизировать std::sync::nonpoison и сделать Mutex по умолчанию таким, а отравление оставить отдельной обёрткой Poison<T>.

Библиотека parking_lot работает без отравления замков, на неё перешли rust-analyzer и Mozilla, из тех примеров, что приводит автор.

ОграниченияПока это обсуждение команды libs, а не решение.
