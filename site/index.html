01Java4Shell: в OpenJDK дыра, через которую берут Jenkins и Jira

thehackernews.com7 источниковдоступнотакже: The Record, The Hacker News, SecurityWeek, The Register и ещё 3

Почему важноЕсли на сервере стоит Java на процессоре Intel или AMD с AVX-512, патч Java4Shell нужен сейчас; на ARM уязвимый код не работает.

В OpenJDK нашли дыру Java4Shell: через неё можно удалённо выполнить код в Jenkins, Jira, Confluence и Keycloak, а в некоторых приложениях даже без учётки. Ошибка в аппаратно ускоренном декодере Base64 портит память JVM. CISA велела срочно ставить патч, а VulnCheck отмечает, что для атаки на конкретную цель всё равно нужна работа под каждую систему.

Разбор

Уязвимость в быстрой версии декодера Base64 в OpenJDK проявляется при обработке строк на определенных процессорах x86-64 с поддержкой векторных инструкций. Ошибка позволяет переполнить буфер памяти JVM без авторизации, хотя для реального выполнения кода исследователям пока приходится подстраивать структуру памяти под конкретную систему.

  1. Уязвимость отслеживается под кодом CVE-2026-114938 и оценена исследователями в 9.2 балла по шкале CVSS 4.0.
  2. Затронуты версии Java 17.0.6 и выше на ветке 17, а также Java 21, 25 и 27, плюс сборки GraalVM и Java SE 8 Performance Pack 8u511b33-perf.
  3. Уязвимый код работает только на процессорах Intel и AMD с поддержкой инструкций AVX-512 VBMI, включая линейки Xeon Ice Lake, Sapphire Rapids, Emerald Rapids, Granite Rapids и AMD Zen 4 или новее.
  4. Для проверки наличия инструкций процессора на Linux используется команда с фильтрацией флагов в /proc/cpuinfo.
  5. Исправления уже выпущены в новых минорных релизах Oracle Java, Amazon Corretto, Azul Zulu и SapMachine, в то время как Red Hat еще готовит патчи для своих систем.

Обновленные сборки Java доступны на сайтах вендоров — в репозиториях Oracle, Amazon Corretto, Azul Zulu и SAP SapMachine.

ОграниченияУязвимость проявляется только на процессорах x86-64 с поддержкой AVX-512 VBMI; неудачная попытка атаки может уронить службу Java.

02Astra от OpenAI на 20–600% дешевле, но отзывы на неё разошлись

latent.spaceдоступно

Почему важноЗначит, за те же задачи можно платить меньше, но модель лучше выбирать под задачу, потому что отзывы на Astra пока разные.

OpenAI выпустила GPT-6.2 Astra и Sol. По оценке newsletter, Astra стоит на втором месте среди фронтир-моделей и дешевле на 20–600%, а Sol, скорее всего, станет основной рабочей моделью. Ранние тестировщики расходятся во мнениях о том, как с Astra работать.

Разбор

OpenAI выпустила новые модели GPT-6.2 Astra и Sol прямо накануне выхода конкурентов на биржу, сделав акцент на максимальной эффективности интеллекта на каждый потраченный доллар. Astra позиционируется как мощная фронтир-модель с существенным удешевлением запросов, хотя ранние тестировщики отмечают специфические артефакты в ее работе.

  1. Новые модели доступны в ChatGPT Work и Codex для платных тарифов, а также через API под именами gpt-6.2⁠-⁠astra и gpt-6.2⁠-⁠sol.
  2. Цены на API для Astra составляют $8 за миллион входных токенов, $0.40 за кэшированный ввод и $40 за вывод; модель Sol сохраняет расценки предшественника на уровне $2, $0.10 и $10.
  3. Обе модели поддерживают контекст в 1 млн токенов и лимит вывода в 128K токенов.
  4. На юридическом тесте Harvey LAB-AA конфигурация Astra для Enterprise с правовым поисковым индексом показала результат 20.8% против 15.0% у базовой версии.
  5. В тестах агентов Astra набрала 67.2% в OpenWorldEngineer от Mercor и лидирует в ряде других бенчмарков по коду и робототехнике.

Модели доступны разработчикам через OpenAI API и корпоративным клиентам в ChatGPT Work и Codex.

ОграниченияЧасть ранних тестировщиков и разработчиков критикуют новые модели за артефакты обучения с подкреплением и особенности работы сабагентов.

05Malware через Optimizely уже на 178 сайтах: CNN, BBC, Zoom

xakep.ruприменяют

Почему важноЗначит, один скомпрометированный скрипт поставщика бьёт сразу по всем его клиентам, а посетитель не видит, что зараза пришла не с самого сайта.

Взломщики подменили скрипты Optimizely, сервиса A/B-тестов, который встраивают на сайты. Скрипты грузятся на страницах клиентов автоматически, поэтому посетители начали получать малварь; её нашли как минимум на 178 сайтах, включая CNN, BBC, Zoom, Salesforce и GitLab.

Разбор

Взломав процесс регистрации аккаунтов на платформе A/B-тестирования Optimizely, злоумышленники внедрили вредоносный код в поле Project JavaScript клиентских проектов. Измененные скрипты автоматически подгружались через официальную CDN-инфраструктуру сервиса на сайты тысяч крупных компаний, атакуя браузеры посетителей.

  1. Исследователь Скотт Хелм из Report URI проверил 1611 сниппетов и нашел вредоносный код в 188 из них, которые принадлежали 178 организациям.
  2. Загрузчик скачивал основной вредонос track.js с домена 1688360[.]cc, который искал криптовалютные кошельки, перехватывал данные банковских карт и делал скриншоты страниц.
  3. Для владельцев iPhone и iPad малварь дополнительно задействовала эксплоит-киты Coruna и DarkSword под разные версии iOS.
  4. Инъекции начались утром 16 ноября 2026 года, но уже к вечеру того же дня вредоносный код оперативно удалили со всех затронутых проектов.
  5. Платформа Optimizely завершила активные сессии, отозвала токены и сбросила настройки доступа для пострадавших учетных записей.
ОграниченияАтака затрагивала пользователей сайтов, использующих скрипты Optimizely; платежные формы через изолированные iframe вроде Stripe и Adyen скрипт прочитать не мог.

06В PyPI пакет agent-framework от Microsoft заразили стилером

thehackernews.com2 источникаприменяюттакже: SecurityWeek

Почему важноЗначит, срабатывает при каждом запуске Python, и заражённая версия крадёт облачные ключи у любого, кто её установил.

Версии 1.26.1 и 1.26.2 пакета agent-framework на PyPI, выложенные с интервалом в 33 минуты 17 ноября, несут стилер, то есть программу, которая тайком ворует данные. Он срабатывает при каждом запуске Python и ворует учётки Azure, Azure DevOps и GitHub Actions.

Разбор

Пакет agent-framework на PyPI был скомпрометирован неизвестными злоумышленниками, которые смогли загрузить две вредоносные версии с интервалом в 33 минуты. Пакет добавляет файл конфигурации Python, запускающий стилер при каждом старте интерпретатора даже без явного импорта самого пакета.

  1. Затронуты версии 1.26.1 и 1.26.2, которые устанавливают файлы .pth (соответственно agent_framework_meta.pth и af_runtime_diag.pth) в корне каталога site-packages.
  2. Малварь собирает переменные окружения, файлы учетных данных Azure CLI, npm, pip, Docker, Hugging Face, а также запрашивает новые токены через локальный метаданный сервис IMDS по адресу 169.254.169[.]254.
  3. Все собранные данные сжимаются алгоритмом zlib, кодируются в Base64 и отправляются методом POST на конечную точку webhook[.]site.
  4. Версия 1.26.2 дополнительно собирает OIDC-токены GitHub Actions и расширяет поиск учетных данных по переменным окружения.
  5. Пакет имеет около 190 000 загрузок в месяц, поэтому пользователям рекомендуется зафиксировать версию 1.26.0 и проверить логи на предмет запросов к webhook[.]site.

Пакет заблокирован и помещен в карантин на репозитории PyPI.

ОграниченияВредоносный код срабатывает при любом запуске Python в затронутом окружении независимо от того, импортируется ли сам agent-framework.
